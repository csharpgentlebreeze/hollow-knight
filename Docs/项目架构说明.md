# 项目架构说明（QFramework 版）

> 本文档描述迁移完成后的当前架构现状：分层规则、各模块的实际实现、目录结构、
> 以及新增代码时应该遵循的约定。历史演进过程见同目录下的
> `QFramework迁移工作日志.md`。

## 总览

项目使用 [QFramework](https://github.com/liangxiegame/QFramework)（核心 Architecture
+ ResKit + UIKit + AudioKit + PoolKit + FSMKit 全套 Toolkits）作为架构框架。
`Assets/QFramework/` 是框架代码（不要在里面改业务代码），业务代码全部在
`Assets/Scripts/` 下，沿用项目历史习惯，**没有统一的自定义命名空间**（除了
`Player`、`Enemy` 两个 FSM 相关命名空间），新代码默认也写在全局命名空间，
只通过 `using QFramework;` 引入框架类型。

全局唯一的架构根节点：

```csharp
public class GameArchitecture : Architecture<GameArchitecture>
{
    protected override void Init() { ... }
}
```

任何地方都可以用 `GameArchitecture.Interface` 拿到这个单例（`Architecture<T>` 自带）。

## 分层规则（QFramework 标准规范）

- **Controller**（`MonoBehaviour : IController` 或纯 C# 状态类）：
  可以直接 `this.GetSystem<T>()`/`this.GetModel<T>()`/`this.GetUtility<T>()` 读数据；
  **修改数据必须走 `this.SendCommand(new XxxCommand())`**，不允许直接改 Model。
- **System / Model**：状态变化通过 `this.SendEvent<T>()`（强类型事件结构体）或
  Model 上的 `BindableProperty<T>`（可直接 `.Register(...)` 监听）通知上层；
  **禁止反向直接调用 Controller**。
- **无副作用查询**用 `this.SendQuery(new XxxQuery())`；纯粹"播放一个音效"这类
  无状态调用直接调用 Utility 方法（如 `this.GetUtility<IAudioUtility>().PlaySound(...)`），
  不需要小题大做包成 Command。
- 想要获得以上这些扩展方法（`GetSystem`/`GetModel`/`GetUtility`/`SendCommand`/
  `SendEvent`/`RegisterEvent`/`SendQuery`）的类，**必须实现 `IController`**：
  ```csharp
  public class Foo : MonoBehaviour, IController
  {
      public IArchitecture GetArchitecture() => GameArchitecture.Interface;
  }
  ```
  这是一个纯静态类型约束（extension method 要求 receiver 静态类型满足
  `ICanGetUtility`/`ICanGetSystem`/... 等接口），只继承自一个 `IController` 的类
  **不会**自动获得这个能力——除非父类本身已经 `: IController`，子类才会随继承一起获得。

## 模块映射表（旧 → 新）

| 旧实现 | 新实现 | 备注 |
|---|---|---|
| `Singleton<T>` / `BaseManager<T>` | 删除 | 数据放入对应 `AbstractModel` |
| `MonoSingleton<T>` | 删除 | 所有 manager 改为 `MonoBehaviour : IController` + 对应 `IXxxUtility`，经 `RegisterUtility`/`GetUtility<T>()` 访问 |
| `EventManager`（字符串键） | `TypeEventSystem`（QFramework 内置） | 强类型事件结构体见 `GameEvents.cs` |
| `MonoManager`/`MonoController` | `IMonoUtility` + 内部 `MonoController` | `this.GetUtility<IMonoUtility>()` |
| `PoolManager`/`PoolData` | `IObjectPoolSystem`/`ObjectPoolSystem` | 按路径分池的 `Queue<GameObject>` 语义不变，`Get`/`Push`/`ClearPool` 签名不变 |
| `ResourceManager` | `IResSystem`/`ResSystem` | 内部用 ResKit `ResLoader` + `"resources://"` 前缀，资源目录/打包方式不变 |
| `UIManager`（旧） | `IUIUtility`/`UIManager`（新） | 对外方法名不变；借用 UIKit 的 `UIPanel` 作为 `BasePanel` 基类，其余（层级/回退栈）仍自研 |
| `BasePanel`（旧） | `BasePanel : UIPanel, IController`（新） | `OnShow`/`OnHide` 转发到 `ShowMe()`/`HideMe()`，子类零改动 |
| `AudioManager`（旧） | `IAudioUtility`/`AudioManager`（新） | 全局 2D 音效/音乐走 AudioKit；3D 定位音效与 `AudioMixer` 分组仍手写，见下方"AudioKit 混合方案" |
| `ScenesManager` | `ISceneSystem`/`SceneSystem` | 不挂节点的 `AbstractSystem`（原实现无场景挂载，也无调用方需要保留 Mono 形态） |
| `InputManager`（旧） | `IInputUtility`/`InputManager`（新） | **保留 `MonoBehaviour`**（场景手工挂载 + `PlayerInput` 序列化引用），自注册 |
| `GameManager`（旧） | `IGameUtility`/`GameManager`（新） | **保留 `MonoBehaviour`**（场景手工挂载），`gameState` 代理到 `IGameStateModel` |
| `IState` + Player 状态类 | FSMKit `AbstractState<States, PlayerController>` | 构造函数 `(FSM<States> fsm, PlayerController target)` |
| `PlayerFSM` | `PlayerController : MonoBehaviour, IController` | 类名改了，文件名/GUID 不变，场景引用不受影响 |
| `EnemyFSM` + 子类 | `EnemyController`（基类）+ `Crawler`/`Gruz`/`Vengefly`/`GruzMother` | 同上，类名改了但文件名/GUID 不变 |
| `Geo.cs`/`Health.cs`/`GeoCollect.cs` 等 | 未改动 | 已经足够独立，未强依赖被替换的 manager API |

## 各模块使用方式速查

### 拿到某个能力

```csharp
// Controller 内（this 必须是 IController）
this.GetSystem<IResSystem>().Load<T>("路径");
this.GetModel<IGameStateModel>().State.Value;
this.GetUtility<IAudioUtility>().PlaySound("AudioClip/xxx", false);
this.GetUtility<IUIUtility>().ShowPanel<BasePanel>("SomePanel");
this.GetUtility<IInputUtility>().pause.performed += (ctx) => { ... };

// FSM 嵌套状态类内（用已有的 manager/target 字段，而不是 this）
manager.GetUtility<IAudioUtility>().PlaySound(...);
```

### 修改状态（走 Command）

```csharp
public class SomeCommand : AbstractCommand
{
    protected override void OnExecute()
    {
        this.GetModel<IGameStateModel>().State.Value = GameState.Playing;
        this.SendEvent<ContinueEvent>();
    }
}
// 调用方：GameArchitecture.Interface.SendCommand(new SomeCommand());
// 或 Controller 内：this.SendCommand(new SomeCommand());
```

### 监听事件

```csharp
this.RegisterEvent<PausedEvent>(OnPaused).UnRegisterWhenGameObjectDestroyed(gameObject);
```

### 新增一个 Utility（跟 `IInputUtility`/`IGameUtility`/`IUIUtility`/`IAudioUtility` 同款模式）

1. 定义接口 `IXxxUtility : IUtility`，声明对外方法；
2. 让承载类实现 `MonoBehaviour, IController, IXxxUtility`（或纯 C# 类实现 `IUtility` 即可，不需要 Mono）；
3. 场景手工挂载对象（如 `InputManager`/`GameManager`）：在自己的 `Awake()` 里
   `this.GetArchitecture().RegisterUtility<IXxxUtility>(this);`；
   动态创建对象（如 `UIManager`/`AudioManager`）：在 `GameArchitecture.Init()` 里
   `new GameObject(...)` + `AddComponent<T>()` + `RegisterUtility<IXxxUtility>(...)`。

## 时序安全规则（务必遵守，Phase 5/6 都因违反过这条规则而返工过）

Unity 只保证"整个场景所有对象的 `Awake()` 全部执行完"发生在"任何对象的 `Start()`
执行之前"，**不保证不同对象的 `Awake()` 之间的相对顺序**，也不保证
`GameArchitecture.Init()`（在某个较早的 `Awake()` 里被首次触发）执行时，其他还没轮到
`Awake()` 的对象已经初始化好。

规则：
- 一个组件的 `Awake()` 里**只能**摸自己的字段/自己身上的组件（`GetComponent<T>()`），
  **不能**跨组件访问其他 Controller/System/Utility 的状态（哪怕是通过
  `this.GetUtility<T>()` 拿到的东西，只要会用到对方尚未在自己 `Awake()` 里初始化完的字段）。
- 跨组件/跨系统的依赖必须延后到 `Start()`、事件回调（按钮点击、
  `InputAction.performed +=`、`OnTriggerEnter2D` 等）或协程里执行。
- `GameArchitecture.Init()` 本身是一次性同步执行完的普通 C# 方法（不受 Unity 生命周期
  阶段影响），`RegisterSystem`/`RegisterUtility`/`RegisterModel` 之间的顺序完全由
  `Init()` 内的代码顺序决定，与"谁先调用 Awake()"无关——但 `Init()` 内部如果用
  `AddComponent<T>()` 动态创建 Mono 组件，会**同步立即**触发该组件的 `Awake()`，
  所以 `Init()` 内的注册顺序必须让"被依赖的 System/Utility"排在"依赖它们的
  `AddComponent<T>()` 调用"之前（例如 `UIManager`/`AudioManager` 的 `Awake()` 会用到
  `IResSystem`，所以 `RegisterSystem<IResSystem>` 必须写在它们的 `AddComponent` 之前）。

## AudioKit 混合方案（为什么 `AudioManager` 里既有 AudioKit 调用又有手写实现）

QFramework AudioKit 的播放全部走它内部的 `AudioManager`（QFramework 自带的，与本项目
`AudioManager` 同名不同类），其 `AudioSourceProxy`/内部 `AudioSource` 均为 `internal`，
且新建的 `AudioSource` 一律挂在 AudioKit 自己的常驻对象下，因此：
- **无法**暴露 `spatialBlend`/min-max distance/rolloff 等 3D 定位音频参数；
- **没有**把播放出的 `AudioSource` 路由到指定 `AudioMixer Group` 的钩子。

所以：
- 按名字加载播放的全局/2D 一次性音效与背景音乐 → 用 AudioKit（`PlayMusic`/`PlaySound`/
  `PauseMusic`/`ResumeMusic`/`StopMusic`），本来就不需要 3D 定位或 Mixer 分组特殊处理；
- 敌人身上的 3D 定位音效（`AudioController.cs`）、基于 `AudioMixer` Group 的音量控制、
  直接操作 Inspector 已配置 `AudioSource` 的功能（`PlayAudio`/`PauseSound`/`UnPauseSound`/
  `StopSound`）→ 继续手写，不迁移；
- `SetSoundVolume` 同时驱动旧 `AudioMixer` "Sound" 分组 与 `AudioKit.Settings.SoundVolume`，
  确保一个音量滑条能同时影响两条播放路径。

如果未来要彻底统一到 AudioKit，需要等它开放自定义 `AudioMixer Group` 路由或 3D 参数的
公开 API，或者自己实现一个自定义 `IAudioLoader` 去接管。

## UIKit 借用范围（为什么 `UIManager` 不是 `UIKit.OpenPanel` 那一套）

UIKit 自带的面板管理（`UIKit.OpenPanel<T>`/`UIRoot`/`UILevel`）只有 3 层，且要求一个
项目里没有的 `UIRoot` 预制体，跟项目现有的 4 层（`Bot`/`Mid`/`Top`/`System`）+
自定义"返回上一个面板"栈模型不兼容。因此只借用了 UIKit 的 `UIPanel` 基类
（`Init`/`Open`/`Show`/`Hide`/`Close` 标准生命周期），继续用项目自己的 `UIManager`
做加载（`IResSystem.LoadAsync<GameObject>("UI/" + panelName)`）、挂载到对应层级、
维护面板栈、销毁。`BasePanel` 把 `OnShow`/`OnHide` 转发到项目原有的
`ShowMe()`/`HideMe()` 虚方法，所有具体面板类零改动即可继续工作。

## 已知限制 / 尚未覆盖的边界

- 项目没有自动化测试框架覆盖这些系统，正确性依赖分阶段人工 Play 测试回归。
- `Docs/` 里没有覆盖到的边界脚本（`Geo.cs`/`Health.cs`/`GeoCollect.cs` 等道具类）
  本次未纳入迁移范围，如果后续要改，先确认它们是否引用了已删除的旧 manager API。
- AudioKit/3D 音频的限制见上文"AudioKit 混合方案"一节。
